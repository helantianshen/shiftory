# Shiftory 工程约束

本文记录开发时需要遵守的边界。产品目标见 [产品需求](REQUIREMENTS.md)，启动与部署步骤见 [README](../README.md)。需求、接口契约和代码存在差异时，应核对具体调用链，不能把需求中的目标当成已实现行为。

## 模块与错误边界

- 后端按业务模块组织；`internal/platform/httpserver` 负责 HTTP 适配、权限检查与响应序列化，`importer`、`schedule` 等领域包不依赖 Gin。
- 数据访问使用 `database/sql` 与参数化 SQL。认证、导入任务使用 Repository；部分业务查询仍位于 HTTP 路由文件中，不能假定所有模块已完成统一的三层拆分。
- 工作簿规范化返回 `ValidationError`，保留行号、字段、规则码、修复提示和底层错误链。HTTP 层映射为 `INVALID_WORKBOOK`，通过 `error.details` 暴露 `row`、`fields`、`ruleCode`、`hint`，不直接暴露内部堆栈或 SQL。
- 前端导入错误应展示行号、字段和修复提示，最终校验与授权仍由后端负责。

## 排班与导入一致性

- `migrations/00003_global_user_schedules.sql` 定义正式日排班按 `(user_id, work_date)` 唯一。工作区用于授权、班次映射及导入上下文，不能据此建立同一用户同一天的另一份正式排班。
- 该迁移会清空排班、修订、导入任务及相关记录。部署前必须检查迁移版本和数据影响，Down 只恢复索引，不恢复被清空的数据。
- 排班保存班次快照；修改班次定义不能反向改变已保存排班。跨日归属开始日期，缺失记录不等于休息。
- 导入预览保留原排班 ID 和版本；提交时重新核对并在一个事务中写入选中的排班、修订和任务状态。导入撤销检查写入后的版本与来源，拒绝覆盖后续修改。
- 图片识别只生成草稿，经领域校验、班次映射和人工确认后才能写入正式排班。不确定项不能自动写入。
- 原文件通过存储接口访问。文件写入与 MySQL 事务不是同一事务，数据库提交失败后的文件删除属于补偿操作。

## 图片任务运行

- API 是唯一长期运行的后端入口，迁移程序独立执行；AI 启用时 API 创建 Runner 和固定容量的 ants 协程池。
- MySQL 是可靠任务队列，Channel 仅合并唤醒信号；任务入库并提交后才唤醒 Runner，轮询负责兜底发现任务。
- 领取任务使用行锁与 `SKIP LOCKED`，通过租约、心跳和重试恢复中断任务，结果写入检查任务状态与租约所有者。
- 并发数、轮询间隔、租约和 AI 超时由后端配置控制。停机需要取消任务上下文并等待 Runner 退出。

## 配置、日志与部署

- API 与 migrate 共用 `--env` 和 `--config`，默认生产模式；非空进程环境变量优先于 YAML，其次使用内置默认值。后端不加载 env 文件，前端继续使用 Vite 的 `.env*` 与 `VITE_*`。
- 未显式指定配置时，按工作目录、父目录、祖父目录查找首个 `config/<模式>.yaml`；文件不合并。显式路径缺失、非法 YAML、未知键或非法值会报错。相对路径以进程工作目录为基准。
- 样例配置只保存可分发值；实际 YAML、JWT 私钥、模型密钥与上传文件不能进入版本控制。生产部署需要持久化上传目录与 JWT 密钥。
- 开发日志默认 `debug` 与文本格式，生产默认 `info` 与 JSON；支持显式覆盖。请求日志包含请求 ID、路径、状态和耗时，不记录令牌、API Key 或图片内容。
- PowerShell 开发启动器先迁移再启动 API 与前端；GoLand 组合配置不自动迁移。`-ValidateOnly` 检查工具和配置路径，不能替代 Go 加载器的配置校验。
- Linux 启动脚本透传模式与配置参数；systemd 使用显式 YAML 路径。Docker 入口先迁移再启动 API，Compose 使用 `COMPOSE_DISABLE_ENV_FILE=1` 避免额外隐式加载根目录 env 文件。

## 成员邀请与前端约定

- 邀请请求的邮箱和用户名二选一。用户名必须对应有效用户，由后端解析为规范化邮箱；邮箱模式保留令牌邀请和接受流程。
- Pinia 管理用户、工作区与主题等界面状态，服务端业务数据由请求层负责刷新。当前工作区不是后端鉴权依据，认证令牌不能持久化到浏览器存储。
- 导入确认框采用中文“确认／取消”，展示六类导入结果的说明。状态与分类可显示小写，API 枚举和业务判断保持原值。
- 六套浅色主题应同时影响侧边栏、导航选中态和主内容区域，语义颜色保持稳定。

## 实现边界与验证

- 正式排班查询已按用户与日期读取，但 `internal/importjob/image_processor.go` 的 `loadExisting` 仍附带工作区条件。跨工作区图片导入的预览分类不能仅凭全局唯一索引推断为正确。
- `internal/platform/httpserver/calendar_routes.go` 对未离开的成员允许展示其既有排班，离开成员按离开日期截断；查询成员集合还会检查成员关系与查询区间是否相交。不能将其描述为对每一天都严格应用加入、离开区间。
- 产品需求中的功能清单是验收范围。判断前端完成度需检查实际源码和构建输入；不能沿用历史计划中的完成标记或旧测试结果。
- 后端执行 `go test ./... -count=1`、`go vet ./...`；数据库集成测试需要兼容迁移的 MySQL 8.4 和隔离的测试数据库。前端需分别验证测试、类型检查和生产构建。
- PowerShell 架构、开发工具和 GoLand 检查见 `scripts/tests/`。真实图片模型识别、数据库任务恢复和部署运行需要相应运行环境，静态检查不能代替这些验收。
