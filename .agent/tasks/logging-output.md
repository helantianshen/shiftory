# 生产日志双输出与大小限制

更新时间：2026-10-06
状态：B 方案已实现，验证通过；已确认仓库无剩余测试代码或临时验证文件

Git 交付：2026-10-06 用户授权提交本次修改并推送 origin/main，二进制不纳入提交；具体结果以 Git 记录为准

用户决定：同步轮转并保留固定数量备份。默认单文件 20 MiB、2 个备份，总内容上限 60 MiB；通过 log.file.path/max_size_mb/max_backups 配置，大小为正整数，备份数允许为 0。非空环境变量可覆盖，没有热更新

行为：development 保持已有控制台格式、等级、颜色和来源字段；production 固定文本控制台及 JSON 文件，两者按 log.level 过滤，默认 info。log.format 仅用于开发模式。日志同步写入，不增加后台日志队列

轮转：写入前检查；超限时先删除最旧备份，再移动编号并创建新文件。编号 .1 为最新备份。备份数 0 时先截断当前文件。单条记录大于上限时拒写文件，控制台保留原日志并报告；轮转或文件写入失败后停止文件写入直到重启，控制台继续输出并报告

启动：删除超限和超过保留数量的规范编号备份，超限当前文件清空；只管理配置文件及其规范数字后缀，不删除其他文件。路径或清理失败时启动失败。日志目录 0750，新文件 0600

入口：API 默认 var/logs/shiftory.log，生产 migrate 使用 shiftory.migrate.log，避免两个进程共用文件；两套文件分别计算限额，默认合计 120 MiB。开发 migrate 保留标准 log 行为；生产致命错误按 ERROR 输出，避免被 warn/error 等级过滤。配置摘要仍按原控制台标签输出

约束：每套文件仅一个进程写入，不允许外部修改或共同写入；上限按文件内容字节数计算，不包括文件系统开销、其他日志或 systemd journal。限额限制文件增长，不代表整个进程内存限制。部署默认 var 已由服务用户拥有并在 systemd 可写路径中；自定义路径需自行满足权限约束

修改：日志模块、新配置结构与校验、API/migrate 入口、公开 YAML 样例、README、部署说明和工程约束；忽略默认根目录 var/logs 下的日志及备份。本地实际 YAML 和二进制未修改
