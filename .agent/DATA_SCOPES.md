# 模块数据范围

正式排班按用户和日期全局唯一。工作区是团队成员、角色、班次、导入任务和团队查询的边界；个人数据共享不授予任意工作区读取任意用户的权限。

| 模块 | 数据范围 | 工作区的作用 |
| --- | --- | --- |
| 登录、个人资料、密码、主题 | 当前用户 | 无；主题和当前工作区选择属于用户偏好 |
| 我的排班、编辑、批量设置、修改历史 | 本人全局排班 | 无需加入工作区；新的预设班次在编辑框显式选择来源 |
| 我的邀请 | 当前用户收到的邀请 | 列表跨工作区；接受后创建相应工作区成员关系 |
| 工作区列表、创建 | 当前用户可访问的工作区集合 | 选择团队上下文，不筛选个人排班 |
| 概览 | 当前工作区团队统计＋本人全局排班统计 | 人数、共同休息、待确认导入按工作区；个人完整度和下一次工作／休息来自全局排班，日期窗口沿用概览的工作区日期 |
| 团队日历 | 当前工作区成员的全局排班 | 决定成员集合和历史日期可见范围；空选默认全部现有成员及查询区间内的历史成员 |
| 排班管理 | 当前工作区成员的全局排班 | 决定可管理对象及角色；修改会影响该成员在所有工作区看到的排班 |
| 导入排班、预览、提交、撤销 | 当前工作区导入任务 | 决定目标成员、班次映射和权限；提交后写入目标用户全局排班 |
| 我的导入记录 | 当前工作区中本人上传的任务 | 按工作区与上传者筛选，不是跨工作区任务汇总 |
| 团队导入记录 | 当前工作区任务 | 管理员可只读查看团队任务，详情链接携带工作区 ID |
| 成员与角色、发出邀请 | 当前工作区 | 成员关系和授权独立，邀请不可覆盖已有有效成员 |
| 班次与别名 | 当前工作区 | 定义及匹配独立；正式排班存储快照 |
| 工作区设置、转让、删除、审计 | 当前工作区 | 设置与管理权限独立；删除保留个人排班和修订 |
| 导入原文件与识别草稿 | 所属工作区的导入任务 | 下载和修改沿用任务授权，不因个人排班共享而开放 |
| 图片 Worker、数据库连接、日志与运行配置 | API 进程 | Worker 可处理各工作区任务，任务本身仍记录工作区及目标用户 |

侧栏“概览”独立显示，其余入口分为“个人”和“工作区”两组。工作区组中的管理菜单按当前工作区角色显示；“我的导入记录”属于工作区组。

前端通过路由 `meta.dataScope` 声明 personal 或 workspace，顶部工作区选择器与页面重建只应用于 workspace 页面。个人排班缓存按用户和日期标识，团队缓存按工作区标识；任何正式排班变更仍使所有工作区派生数据失效。

个人排班接口为 `/api/v1/me/schedules`，目标身份只能来自认证令牌。团队排班接口继续通过 `/workspaces/{workspaceId}/...` 检查成员和角色。无来源的个人排班写入可空 workspace_id；来源字段不作为排班唯一性或所有权依据。
