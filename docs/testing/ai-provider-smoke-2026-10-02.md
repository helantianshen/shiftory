## 输入与实际内容检查

文字案例明确描述 2026-10-01 至 10-07：周一至周五 09:00–12:00 和 13:00–18:00 工作，周末休息，10-03 为 22:00–次日 06:00 的例外；不额外应用法定节假日或调休。对最终模型输出做人工内容对照，两家均正确概括，issues 为空。

## 发现与修正

1. DeepSeek 复杂文字首次未完整结束，约 18.46 秒后被测试入口拒绝；当时只记录通用错误，没有结束原因和 token 数，无法确认具体原因。同输入复测成功。
2. 复测时 DeepSeek 提出了人员名单、岗位人数及薪酬等越界疑问。测试系统提示此前没有明确单成员导入边界，已补充“成员已由系统确定，只提取日期、状态、时间及跨日信息”。再次实测字节和 DeepSeek 均成功，issues 为空。
3. 非正常结束的诊断现包含白名单化 finish_reason 和 completion_tokens，仍拒绝截断结果。增加两适配器的模拟 length/4096 回归测试；真实失败原因没有被追溯确认，不将 mock 的 4096 当作首次真实返回证据。

未修改真实模型配置中的 token 上限，也未通过自动提高上限掩盖首次失败。正式设计仍需处理空／截断输出、路由切换和有限重试。

## 执行方式

- `-run -provider all -text ...`：复杂文字，两家分别调用。
- `-run -provider all -image testdata/schedule.png -text ...`：合成图片，两家分别调用。
- `-run -provider auto -text ...`：优先级与首个成功即结束。
- 临时 0600 配置中的字节连接故障注入，再 `-run -provider auto -image ...`：验证切换；临时文件执行后删除，实际配置未改变。
- DeepSeek 单独复测及提示边界修正后两家再测。

前一轮共 9 次真实模型请求、1 次本地连接失败注入。8 次真实请求成功，1 次真实请求未完整结束；这是小样本执行记录，不是供应商可靠率或性能基准。最终复杂文字耗时约字节 1.96 秒、DeepSeek 14.61 秒，受模型状态及网络影响，不作性能结论。

## 中转站补测

用户填写的中转站配置位于样例文件，已迁移至权限 0600 的实际配置，并清空样例凭据。三个模型均已配置。初始中转站地址为网站根路径，文字与图片请求返回 HTTP 200 的 HTML，不能视为模型成功；补充 `/v1` 后验证成功，已将经验证的 API 地址写入实际配置。

- 复杂文字通过，约 9.84 秒；日期范围、工作日两段班次、周末休息及 10-03 跨日例外均与输入一致，issues 为空。
- 合成图片通过，约 5.05 秒；三个日期、工作／休息、时间和次日标记正确，issues 为空。
- 临时配置将字节指向不可用本地端口：字节连接失败后确实调用中转站，中转站输出未通过 JSON 校验，随后 DeepSeek 成功返回正确图片结果。该次验证的是三家顺序和无效输出后的兜底，不能称为中转站成功接管。
- 对同一图片提示单独复测，中转站在 `json_object` 下返回 Markdown 代码围栏；临时改为 `json_schema` 的一次测试也出现相同情况。实际配置保留 `json_object`，未自动切换参数或剥离围栏。

中转站基础文字与识图能力可用，但当前模型的裸 JSON 输出不稳定，结构化输出验收尚未全面通过。测试入口增加安全的 HTTP 正文格式、Markdown 围栏及字段数量诊断，不输出原始失败正文或密钥；新增 HTTP 200 HTML 拒绝回归测试。正式适配需按 Spec 处理兼容性并重新验收。
